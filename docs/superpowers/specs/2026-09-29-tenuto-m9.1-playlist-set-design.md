Status: approved in conversation on 2026-09-29. It is ready for an implementation plan. The design below is the agreed contract; the code does not yet match it.

Branch: `refactor/m9.1-playlist-set`, from `main` at `67942e8`.

Context:
- The roadmap is [`2026-09-29-tenuto-m9-architecture-deepening.md`](2026-09-29-tenuto-m9-architecture-deepening.md), §3; it lands in PR #30.
- Domain terms (cursor, owned entry, playing and viewed playlist, successor, session's and persisted current media) are defined in the root `CONTEXT.md`, also in PR #30.

This is the first of the three M9.1 items. The versioned JSON file module and resume intent are separate PRs, and nothing here depends on them.

## 1. Decision

The M8 playlist rules are enforced by convention today, spread across four modules. This refactor creates one module, `PlaylistSet`, that owns them. The compiler then keeps every write path inside that module.

This is a pure refactor:
- No user-visible behavior changes.
- `state.json` stays at schema 4, and its serialization and round trip do not change.
- The `LoadTarget::Legacy` path still clears the playing playlist's cursor; roadmap M9.3 retires it.
- There is no CHANGELOG entry.

## 2. What exists today

- **The model.** `PersistedState` (`src/persistence/model.rs:59-78`) holds `playlists: Vec<Playlist>`, `playing`, and both ID allocators. It exposes mutable access through `playlist_mut` (:278) and `queue_mut` (:295), plus the operations `enqueue`, `create_playlist`, `rename_playlist`, `remove_playlist`, `repoint_current_media` and `set_playing` (:318-401).
- **Session's edits.** `Session` makes 21 mutation calls through `state.edit()` and those handles. They include `Playlist::set_shuffle` and the `Queue` methods `move_entry`, `remove`, `clear`, `get_mut`, `set_active`, and `QueueEntry::display_mut`/`set_source`.
- **Duplicated rules.** Several rules are written twice:
  - the shuffle pin (`session.rs:463-471`, `:503-504`);
  - the delete checks (`session.rs:639-644`, `model.rs:373-376`);
  - "next, else previous" (`model.rs:379`, `application/runtime.rs:1262-1263`);
  - the cursor's media (`model.rs:389-395`, `queue_codec.rs:493-527`).
- **Three "Default" builders.** `model.rs:203-218`, `queue_codec.rs:244-264` and `queue_codec.rs:267-286` each build a playlist named "Default".
- **Hidden order in adoption.** `Session::adopt_loaded` must call `set_playing` before `queue_mut().set_active`, because `queue_mut` means "the playing playlist's queue" (`session.rs:1136-1139`).
- **Recovery.** `queue_codec::recover_playlists` (:291-541) mixes JSON salvage and rule enforcement within each record, in this order:
  1. rule 3 (the ID);
  2. rule 2 (decode the entries);
  3. rules 4 and 6, entry by entry, with the cap checked before duplicate reassignment;
  4. the membership half of rule 9;
  5. rule 10;
  6. rule 5.

  Then rules 7, 8 and the media half of rule 9 apply to the whole file. The rule numbers are the M8 spec's, §6.
- **Test backdoors.** Tests reach in through `Playlist::queue_mut_for_tests`, `Queue::from_parts_for_tests` and the `pub` `Playlist::from_parts`. `Queue::enqueue` is `pub` and accepts any `IdAllocator`. `Queue::neighbor` ignores shuffle and is still `pub`.

## 3. Rules the set owns

These are the M8 rules, now enforced in one module:

- **S1.** At least one playlist exists (P1).
- **S2.** Entry IDs are unique across all playlists. Neither entry IDs nor playlist IDs are ever handed out twice, including across a restart (P2, §4).
- **S3.** Each playlist's cursor is a member of that playlist or is `None`.
- **S4.** `playing` names a member.
- **S5.** The entry cap is global (P7), and there are at most `MAX_PLAYLISTS` playlists.
- **S6.** A shuffled playlist's pin is its cursor at the moment shuffle was turned on or it was reshuffled. The pin may later point at a removed entry (M8 §7).
- **S7.** A deleted playlist's successor is the next playlist, or the previous one if it was last.
- **S8.** Every mutation is atomic. An operation that fails leaves the set unchanged, and a live edit never silently applies a recovery repair.

## 4. Module layout and visibility

```
src/playlist/mod.rs     Playlist, PlaylistId, Shuffle, PlaylistError, clean_name, splitmix64
src/playlist/queue.rs   Queue, QueueEntry, NewQueueEntry, QueueEntryId, IdAllocator, …  (was src/queue.rs)
src/playlist/set.rs     PlaylistSet, its recovery builder, Deletion, MediaEffect
```

- `src/lib.rs` keeps `pub mod queue` as a re-export of `crate::playlist::queue`, so no existing import path changes.
- Every mutator of `Queue`, `Playlist` and `QueueEntry` is `pub(in crate::playlist)`. That covers `enqueue`, `move_entry`, `remove`, `clear`, `set_active`, `get_mut`, `display_mut`, `set_source`, `set_name` and `set_shuffle`. The unchecked constructors `Queue::from_parts`, `Queue::entry_from_parts` and `Playlist::from_parts` get the same visibility.
- This boundary is a module, not the `PlaylistSet` type, so the module stays small: the three files above and nothing else.
- `PlaylistSet`'s own mutating operations are `pub`. Outside `crate::playlist`, the only way to reach them is to own a `PlaylistSet`. `PersistedState` owns one in a private field and never returns `&mut PlaylistSet` (§6). Integration tests can build a standalone set.
- **Deleted:**
  - `Queue::neighbor`, whose assertions move to `Playlist::neighbor`;
  - `Playlist::queue_mut`;
  - `Playlist::queue_mut_for_tests`;
  - `Queue::from_parts_for_tests`.
- **Kept:** `PlaylistId::from_raw_for_tests`. It only names an ID and cannot break a rule.

## 5. The set's interface

Types are shown for their shape. The plan may adjust names, but not these semantics.

**Reads.** `PlaylistSet` implements `Deref<Target = [Playlist]>`. There is no `DerefMut`. So `len()` counts playlists, and `iter()` and indexing read them in order.

```rust
fn playing(&self) -> PlaylistId
fn playing_playlist(&self) -> &Playlist
fn playlist(&self, id: PlaylistId) -> Option<&Playlist>
fn owner_of(&self, entry: QueueEntryId) -> Option<PlaylistId>
fn find_entry(&self, entry: QueueEntryId) -> Option<&QueueEntry>
fn total_entries(&self) -> usize
fn check_delete(&self, id: PlaylistId) -> Result<(), PlaylistError>   // Unknown, then LastPlaylist
```

`Playlist` and `Queue` stay public and read-only. `Playlist` keeps `id`, `name`, `shuffle`, `queue`, `playback_order`, `neighbor` and `first_in_order`. `Queue` keeps `entries`, `len`, `is_empty`, `active`, `first`, `index_of` and `get`. The set also exposes each allocator's next value, `pub(crate)`, for serialization only.

**Mutations.** Each one is atomic (S8).

```rust
fn enqueue(&mut self, dest: PlaylistId, batch: Vec<NewQueueEntry>) -> Result<Vec<QueueEntryId>, QueueError>
fn create(&mut self, name: &str) -> Result<PlaylistId, PlaylistError>
fn rename(&mut self, id: PlaylistId, name: &str) -> Result<(), PlaylistError>
fn set_shuffle(&mut self, id: PlaylistId, seed: Option<u64>) -> Result<(), PlaylistError>
fn move_entry(&mut self, id: QueueEntryId, direction: Direction) -> Result<bool, QueueError>
fn remove_entry(&mut self, id: QueueEntryId) -> Result<Removed, QueueError>
fn clear(&mut self, id: PlaylistId) -> Result<(), PlaylistError>
fn delete(&mut self, id: PlaylistId) -> Result<Deletion, PlaylistError>
fn adopt(&mut self, entry: QueueEntryId) -> Result<(), QueueError>
fn clear_playing_cursor(&mut self)
fn update_display(&mut self, entry: QueueEntryId, update: &DisplayUpdate) -> Result<bool, QueueError>
fn set_podcast_fallback(&mut self, entry: QueueEntryId, url: Url) -> Result<bool, QueueError>
```

- **`enqueue`**
  - Adds the batch all or nothing, against the global cap, taking IDs from the shared allocator.
  - When the batch is not empty and `dest` is shuffled, it reshuffles in the same step: the new seed is `splitmix64(old seed)`, and the pin is `dest`'s cursor. The set derives the seed itself, so it needs no source of randomness.
  - An empty batch changes nothing: no reshuffle and no new IDs. An unknown `dest` is still an error.
- **`set_shuffle`** pins the playlist's own cursor. `None` turns shuffle off.
- **`move_entry`** returns whether the order actually changed.
- **`remove_entry`** removes the entry from whichever playlist owns it. It clears that playlist's cursor when the entry was the cursor, and returns today's `Removed`, including `selection`.
- **`clear`** empties a playlist and keeps the playlist itself.
- **`delete`**
  - Runs the same check as `check_delete` and fails before changing anything.
  - Always returns `Deletion { successor, current_media }`, with `successor` set on every successful delete (S7), whether or not the deleted playlist was playing.
  - `current_media: MediaEffect` is `Unchanged` unless `playing` moved. Then it is `Set(Some(media))` for the successor's cursor media, or `Set(None)` when the successor has no cursor.
  - `Deletion` is consumed by `PersistedState` and never reaches `Session` (§6).
- **`adopt`** validates that the entry exists, and only then makes its owner playing and sets that playlist's cursor to the entry. On failure it changes neither `playing` nor any cursor.
- **`clear_playing_cursor`** is the Legacy path. Its behavior is unchanged.
- **`update_display`**
  - Serves both callers for a single entry.
  - `DisplayUpdate` moves from `session.rs` to `crate::playlist`, and `session` re-exports it.
  - Absent fields leave existing values intact. A field is written only when it differs. The return value says whether anything changed.
- **`set_podcast_fallback`**
  - Returns `Ok(false)` when the URL already matches.
  - Returns `SourceMismatch` for a source that is not a podcast, as `set_source` does today.
  - Returns `Ok(true)` when it replaces the source.

`PlaylistSet::default()` is the one fresh set: a single playlist named `Default` with ID 1, and the playlist counter at 2. The name `Default` appears as one constant in `crate::playlist`.

## 6. `PersistedState` as the envelope

`PersistedState` keeps the schema version, `current_media`, volume and checkpoints, plus a private `playlists: PlaylistSet`.

- **Reads.** `PersistedState::playlists() -> &PlaylistSet` is the only read path. `playing`, `playlist`, `playing_playlist`, `queue`, `owner_of`, `find_entry` and `total_entries` are removed from `PersistedState`. `queue()`, the shortcut to the playing playlist's queue, is not replaced: callers write `playlists().playing_playlist().queue()`.
- **Mutations** (forwarding option (a), agreed in the design review). `PersistedState` forwards each set mutation through its own `pub(crate)` method, and never hands out `&mut PlaylistSet`. The forwarding methods coordinate fields that have to stay consistent with each other; they do not duplicate any playlist rule.
- **`delete_playlist(id) -> Result<PlaylistId, PlaylistError>`** is the one forwarding method that also acts on the envelope. It applies `Deletion::current_media` to the persisted `current_media` and returns only the successor. Because no caller outside `PersistedState` ever holds a `Deletion`, the effect cannot be left unapplied.
- **Removed:** `playlist_mut`, `queue_mut`, `set_playing`, `remove_playlist`, `repoint_current_media` and `index_of`/`playing_index`.
- **Serialization** writes the same fields in the same order. The allocator values come from the set's `pub(crate)` accessors.

## 7. `Session` after the move

`Session` keeps load correlation, playback ownership, checkpoints and write urgency. Playlist rules leave it.

- **`enqueue`** calls `state.edit().enqueue(dest, batch)` and submits `Ordinary` exactly as it does today, including after an empty batch. The reshuffle moves into the set.
- **`set_shuffle`, `create_playlist`, `rename_playlist` and `move_entry`** forward to the set, with their submission unchanged.
- **`remove_entry`** keeps its order: check the entry exists, invalidate pending loads, release if owned, then remove.
- **`clear_playlist`** keeps its order: check, `vacate`, clear.
- **`delete_playlist`**
  - Runs `state.playlists().check_delete(id)`, then `vacate`, then `state.edit().delete_playlist(id)`, whose own check repeats and cannot fail after the first.
  - `vacate` must run first because it reads the playlist's entries, to find pending targets, and ownership (`owns_playlist`) from the membership that still exists.
  - It returns the successor to the runtime alongside today's `Removal`.
- **`adopt_loaded`**
  - Calls `state.edit().adopt(id)` instead of `set_playing` plus `queue_mut().set_active`.
  - It still ignores the error, because `observe` has already validated the entry.
  - It keeps its before/after `(playing, cursor)` comparison and its submission decision.
  - The Legacy arm calls `clear_playing_cursor`.
- **Display updates.**
  - `apply_display` reads the ids of every entry of a media across playlists, then calls `update_display` for each and ORs the results.
  - `absorb_load_metadata` builds a `DisplayUpdate` from `MediaMetadata`, with the duration tagged `Decoded(provenance)` as today, and calls `update_display` for the one adopted entry.
- **`update_podcast_fallback`** submits `Ordinary` only when `set_podcast_fallback` returns `Ok(true)`.
- **Removed:** `owner_queue_mut`.

The runtime takes the successor from `Session::delete_playlist` when the deleted playlist was the viewed one. This replaces its own index arithmetic at `application/runtime.rs:1225-1265`.

## 8. Recovery

JSON parsing and the persistence diagnostics (`QueueReset` and its problem enums) stay in `queue_codec`. The recovery types in the set name no JSON type and no persistence type.

### 8.1 Division of work

| Owner | Responsibility |
|---|---|
| Codec | The counter scan over every raw record, including records later discarded or beyond a cap. The file-level too-many-playlists diagnostic, noted first. The raw entry count reported in the capacity diagnostic. The order of records (file order). Parsing each record into parts. Mapping repairs to `QueueReset`, with the first problem winning. |
| Builder | The order of stages within a record. Every rule in §3. The final check before any set exists. |

The builder does not claim that its results are independent of call order. Records must be pushed in file order, because that order decides which duplicate keeps its ID and which entries survive truncation.

### 8.2 Parts

```rust
struct RecordParts {
    id: Option<u64>,                      // None: absent or not a number
    entries: Vec<(u64, NewQueueEntry)>,   // decoded, in list order; raw id kept for rules 4 and 9
    cursor: Field<u64>,                   // Absent | Malformed | Value
    shuffle: ShuffleField,                // Absent | BadSeed | Seeded { seed, first: Field<u64> }
    name: Option<String>,                 // already cleaned by clean_name; None if absent or invalid
}
```

`NewQueueEntry::new` performs the same source-and-media check that `entry_from_dto` does today, so the codec never constructs an unchecked `QueueEntry`.

### 8.3 Builder

```rust
PlaylistSet::recovery(entry_ids: IdAllocator, playlist_ids: IdAllocator) -> Recovery
Recovery::push_record(&mut self, parts: RecordParts) -> Vec<Repair>
Recovery::finish(self, playing: Option<u64>, current_media: Option<MediaId>) -> Recovered
```

- The codec supplies the counters, already raised past every ID it saw in the raw file.
- `push_record` applies its stages in this fixed order and returns the repairs in the order it made them. Each repair is tagged with its stage.
  1. **Id** (rule 3). Claim the raw ID, or take a fresh one when it is absent or repeats an earlier record's ID. When the playlist counter is exhausted, the record is skipped: no later stage runs, and the only repair is `IdsExhausted`.

     A record beyond `MAX_PLAYLISTS` is also skipped. It reports `TooManyPlaylists` with no count, and the codec's file-level note has already won the diagnostic slot.
  2. **Entries** (rules 4 and 6), processed entry by entry in list order.
     - First, the cap check: once the global cap is reached, the entry is dropped and reports `OverCapacity`. A dropped entry consumes no fresh ID.
     - Then duplicate reassignment: an ID seen in an earlier playlist gets a fresh ID and reports `DuplicateEntryId`, or reports `IdsExhausted` and is dropped when the entry counter is exhausted.
     - A dropped or reassigned entry that was the raw cursor clears the cursor.
  3. **Cursor** (the membership half of rule 9). `Absent` leaves the cursor `None` silently. Any present field that does not resolve to a member leaves the cursor `None` and reports `DanglingCursor`. That covers `Malformed`, a value that is not a member, and a value the Entries stage cleared. So a reassigned cursor reports `DuplicateEntryId` and then `DanglingCursor`, as today.
  4. **Shuffle** (rule 10).
     - `BadSeed` turns shuffle off and reports `Shuffle`.
     - `Seeded` with `first: Malformed` keeps shuffle, clears the pin and reports `Shuffle`.
     - A numeric `first` that is not a member is cleared silently.
  5. **Name** (rule 5). `None` becomes `Playlist <resolved id>`, silently.
- **`finish`**
  - Rule 7: no surviving record gives one empty `Default` with a fresh playlist ID, or ID 1 when the counter is exhausted, and `current_media` is `Unchanged`.
  - Rule 8: `playing` absent or dangling gives the first playlist, reports `DanglingPlaying`, and sets `current_media` to that playlist's cursor media (`Set(..)`).
  - Rule 9, media half: a playing cursor whose media differs from `current_media` is cleared and reports `CursorMediaMismatch`, and `current_media` is `Unchanged`. Rules 8 and 9 never both apply.
  - It returns `Recovered { set, current_media: MediaEffect, repairs }`. `finish` consumes the builder, so neither a partial set nor an unchecked set ever exists outside it.
- `Repair` is a domain enum in `crate::playlist`. The codec maps each repair to today's `QueueReset`/`PlaylistProblem`/`ActiveProblem` values, and fills in the raw counts it holds (`found`).

### 8.4 Codec merge and precedence

For each record, the codec parses first, holding back its JSON problems and tagging each with the stage it belongs to: a malformed entries array belongs to **Entries**. Then it calls `push_record` and notes problems stage by stage: at each stage, the codec's problem first, then the builder's repairs.

When the builder skips a record at the **Id** stage, the codec drops that record's held JSON problems. This reproduces today's early `continue`, which never decoded the entries of a record it could not keep.

The result is exactly today's first-problem precedence. It is not a numeric rule order: rule 3 comes before rule 2, and the capacity check comes before duplicate reassignment.

### 8.5 Codec policies that stay in the codec

- **A duplicate entry ID within one queue** resets that queue (rule 2, `WholeQueue(DuplicateIds)`). The codec passes an empty `entries` and notes its own problem. Duplicates across playlists are reassigned by the builder.
- **Schema 3 over capacity** resets the whole queue (`recover_queue`), and so does a malformed schema 3 queue. Schema 4 truncates to the global cap in the builder.
- **Schema 3 migration** builds through the same builder:
  1. The codec creates the builder with `entry_ids` raised past the old queue's IDs and `playlist_ids` starting at 2.
  2. It pushes one record: ID 1, name `Default`, no shuffle, the recovered entries and cursor.
  3. It calls `finish(Some(1), current_media)`.

  `recover_queue` keeps its own validation and first-problem result, and now returns parts instead of a `Queue`.
- **An absent or malformed `playlists` field** (rule 1) calls `finish` with no records, using counters from the stored values only, as today.

## 9. Tests

Replace, don't layer: the tests move to the set's interface.

- **New: `tests/m9_playlist_set.rs`**, which tests every rule in §3 through the set's interface.
  - It covers every operation, including atomic failure, the reshuffle on enqueue, the empty-batch no-op, successor on non-playing and playing deletes, the `Deletion` effects, `adopt` validation, and both display-update scopes.
  - It covers recovery through `recovery`/`push_record`/`finish`, including the skipped-record case, the cap before duplicate reassignment, and the three shuffle cases.
- **Ported and deleted: `tests/m5_queue.rs` and `tests/m8_playlist.rs`.** Their domain assertions move to the new suite, and `Queue::neighbor`'s move to `Playlist::neighbor`.
- **Trimmed: `tests/m8_session_playlists.rs`**, down to ownership, invalidation, release and submission.
- **Same scenarios and assertions:** `tests/m8_state_playlists.rs` and `tests/m8_roundtrip.rs`. They keep JSON decoding, migration, diagnostics and checkpoint preservation. Only mechanical accessor edits are allowed: `state.playing()` → `state.playlists().playing()`, `state.queue()` → `state.playlists().playing_playlist().queue()`, and the same kind of edit for the other moved reads.
- **New cases in `tests/m8_state_playlists.rs`** that combine several defects in one file, to pin first-problem precedence:
  - a repeated playlist ID with malformed entries in the same record;
  - over capacity together with a duplicate entry ID;
  - an exhausted playlist counter together with malformed entries in the skipped record;
  - a dangling cursor together with a malformed shuffle;
  - too many playlists together with an early record defect.

  Each case asserts the same `QueueReset` that `main` at `67942e8` reports. The plan captures those values from `main` before the codec changes.
- **Rebuilt fixtures:** `m8_transport`, `m5_transport_rules`, `m8_browser`, `tests/support/views.rs`, and the `#[cfg(test)]` modules of `application/view.rs` and `application/runtime.rs`. They build through `PlaylistSet::default()` and its operations instead of `Queue::enqueue`, `Queue::from_parts_for_tests` or `Playlist::from_parts`.
  - A fixture that needs a particular entry ID gets it from the allocator's order: IDs are handed out from 1, in enqueue order.
  - If a fixture really cannot be expressed that way, the plan records it and decides it case by case. It is not a reason to widen the production interface.
- **Private unit tests stay:** tests of implementation details keep their `#[cfg(test)]` modules, for example the SplitMix64 reference vector in `playlist`.

## 13. Risks

- **Moving `queue.rs` touches many import paths.** The `crate::queue` re-export keeps them compiling. The plan moves the file and adds the re-export first, then changes visibility, so each step builds on its own.
- **Recovery precedence.** The stage-tagged merge in §8.4 is the one place where the codec and the builder have to agree. The multi-defect cases in §9 pin it, against values captured from `main`.
- **`Deref<Target = [Playlist]>`.** It exposes slice reads only. Nothing gets `DerefMut`, so a `&mut PlaylistSet` never becomes a `&mut [Playlist]`.
