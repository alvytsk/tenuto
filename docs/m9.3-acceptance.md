## Decisions

Made with the user on 2026-10-05:

- `tenuto play` is **detached**. It never adds a row, moves a cursor or
  changes which playlist is playing. It still saves its own resume
  position and the volume.
- `play` runs **over `PlayerRuntime`** and keeps its documented keys
  (space, arrows, Home, `-`/`+`, `s`, `p`, `q`, Ctrl-C).

## Found during implementation

- The plan assumed the saved `current_media` was not read on load. It is:
  `PlaylistSet::finish` clears a playing cursor whose media differs
  (`CursorMediaMismatch`). A detached load therefore leaves the saved
  `current_media` to the cursor while one stands. With no cursor it records
  its media as any load does, which `session_policy` and `resume_contract`
  rely on. Pinned by
  `m9_3_detached_session::a_detached_load_leaves_the_saved_current_media_to_the_cursor`,
  `…::with_no_cursor_a_detached_load_is_the_saved_current_media`, and end to
  end by `m9_3_play_leaves_playlists::play_keeps_the_playing_playlist_and_its_cursor`,
  which runs `tenuto play` against a seeded profile and reloads it.
- `app.rs`'s tests moved to what survives: the mirror and progress-gating
  tests to `application/runtime.rs`, the resume-decision and on-disk opener
  tests to `application/profile.rs`.
